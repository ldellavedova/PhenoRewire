# data/

Two small **synthetic** example datasets, so you can run PhenoRewire right after installing it and see what the input tables look like. They contain no real study data. Both are generated by [`dev/benchmarks/fixtures/generate_example_data.py`](../dev/benchmarks/fixtures/generate_example_data.py) and have a known answer: some metabolites change in abundance and rewire, some change in abundance only, some rewire without any change in abundance, and the rest is background.

| Files | Design | Run it with |
|---|---|---|
| `feature_table.csv`, `metadata.csv` | Two groups: 20 reference, 20 case | `phenorewire --config config_phenotype.yaml` |
| `temporal_feature_table.csv`, `temporal_metadata.csv` | One group of 20 subjects, each sampled at 0, 4 and 10 h | `phenorewire --config config_temporal.yaml` |
| `example_molecular_network.graphml` | A small molecular network whose node IDs match the feature IDs above | `--run-2dnetwork` |

## The known answer, and what a run returns

Both tables are built from four blocks of metabolites (`generate_example_data.py` names them in its header):

| Features | In the data | Should be |
|---|---|---|
| `F001`–`F010` | abundance changes **and** correlations are lost | selected, and rewired |
| `F011`–`F020` | abundance changes, correlations kept | selected, **not** rewired |
| `F021`–`F030` | correlations change, abundance identical | selected by connectivity, and rewired |
| `F031`–`F060` | background | neither |

Running the two configs as shipped reproduces this:

| | Phenotype example | Temporal example |
|---|---|---|
| `F001`–`F010` selected / called rewired | 10 / 10 | 10 / 9 |
| `F011`–`F020` selected / called rewired | 10 / **0** | 10 / **0** |
| `F021`–`F030` selected / called rewired | 8 / 8 | 8 / 8 |
| `F031`–`F060` selected / called rewired | 4 / **0** | 1 / **0** |

The second row is the point of the tool: ten metabolites whose abundance changes while their correlations do not are selected, and the rewiring test refuses to call any of them rewired. The third row is the complement — metabolites a differential-abundance analysis cannot see at all. The handful of background features that pass selection are noise at the selection stage, and none of them survives the test against chance.

## The two tables, in short

**Feature table**: one row per metabolite, then one intensity column per sample.

```text
feature_id,mz,rt,name,Sample_01,Sample_02,...
F001,133.014,0.98,lactate,39.9672,89.0768,...
```

**Metadata**: one row per sample; any columns you need to define groups and timepoints.

```text
sample_id,group_label,timepoint
Sample_01,reference,1
```

```text
sample_id,subject,cohort,timepoint
S01_0h,S01,exposed,0
```

What the tables must contain, and what to leave out: [`docs/prepare_your_data.md`](../docs/prepare_your_data.md).

## Your own data

You can keep your tables anywhere: the config points to them, with paths relative to the config file. If you put them here, note that `.gitignore` excludes every other CSV in this folder, so your data are not committed by accident.

A walkthrough of one run on the phenotype example, file by file: [`docs/tutorials/walkthrough.md`](../docs/tutorials/walkthrough.md).
