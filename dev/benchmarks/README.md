# Benchmarks

Every benchmark here runs on **simulated** data, generated by the scripts themselves, with a known answer. No study data are used or needed. The result tables each script produced are committed next to it, so its claims can be checked without re-running anything.

| Script | Purpose | Cite? |
|---|---|---|
| `null_benchmark.py` | Ground-truth benchmark of the released code, including the rewiring null, against DiffCorr and DGCA run through R. Measures specificity, power and the operating range. | **Yes.** This is the benchmark reported in the README and the paper. |
| `effect_size_benchmark.py` | How large a reorganisation has to be for PhenoRewire to detect it *below* the operating range, at 5–12 samples per state. | **Yes**, for claims about small experiments. |
| `rewiring_benchmark.py` | How well `rewiring_score` ranks injected rewired features at 10–50 samples per group. Development check. | No |
| `comparison/method_comparison.py` | Early comparison against a naive fold-change ranking and a *Python re-implementation* of a DiffCorr-style test. Superseded by `null_benchmark.py`, which runs the published packages. | No |
| `profiling/performance_profile.py` | Runtime and memory scaling. | Only for runtime claims |

## `null_benchmark.py` — is the tool safe, and from what sample size?

Four scenarios over 200 metabolites, one block of 20 carrying the signal, 5–25 samples per state, 20 replicates: **N** nothing differs; **A** the block shifts in abundance with its correlation kept (no rewiring); **D** the block shifts *and* loses its correlation (rewiring); **B** the block loses its correlation with identical marginals (rewiring that differential abundance cannot see).

Every PhenoRewire number comes from the package's own functions, not a re-implementation, so the benchmark measures the released code. The two comparators are scored at the pair level at a matched false-discovery rate:

- **DiffCorr** (Fukushima, *Gene* 2013), on CRAN; needs the Bioconductor dependencies `pcaMethods` and `multtest`.
- **DGCA** (McKenzie *et al.*, *BMC Syst Biol* 2016), archived on CRAN — install from the archive or from GitHub. Scored on its BH-adjusted asymptotic p (`--dgca-perm 0`), which matches how DiffCorr is scored.

```bash
python dev/benchmarks/null_benchmark.py                                  # PhenoRewire only
python dev/benchmarks/null_benchmark.py --rscript "Rscript"              # with DiffCorr and DGCA
python dev/benchmarks/null_benchmark.py --rscript "conda run -n rbench Rscript"
```

Each comparator is used if its R package is importable and skipped otherwise, so a partial installation still produces a usable run.

Defaults: scenarios N, A, D, B; 5, 6, 10, 14, 20 and 25 samples per state; 20 replicates; seed 20261014; 1000 selection and 200 null permutations. The run takes a few hours, most of it in the R comparators. `--resume` keeps completed replicates and computes only the missing methods; each replicate is seeded from (scenario, n, replicate) alone, so a resumed run gives the same result as an uninterrupted one.

Outputs, committed: `null_benchmark_runs.csv` (one row per method × scenario × n × replicate), `null_benchmark_summary.csv` (means), and `null_benchmark_figure.png`/`.svg`/`.csv` from `plot_null_benchmark.py`.

**Result.** PhenoRewire never called a difference in N or A, at any sample size. DiffCorr and DGCA both called one in every replicate at 5–6 samples per state, including when nothing differed; they become accurate from about 20 per state. Where metabolites change their partners without changing their level (B), differential abundance selects none of them at any sample size.

Other differential-correlation tools were considered and are not included: DNEA installs but did not complete its stability selection within 15 minutes per dataset at these sample sizes, and its documentation targets 50–500 samples.

## `effect_size_benchmark.py` — what survives below the operating range?

The main benchmark simulates one effect size. This one grows the effect along two axes — how much of the metabolome is involved, and how tightly it is coupled — at 5–12 samples per state, the regime of a strain-dropout design. It imports `null_benchmark.py` from this folder and reuses its comparators.

```bash
python dev/benchmarks/effect_size_benchmark.py --n-grid 5 6 --blocks 20 80 --rhos 0.95 --shifts 1.2 2.0 --reps 10 --rscript "Rscript"
python dev/benchmarks/effect_size_benchmark.py --n-grid 10 12 --blocks 20 80 --rhos 0.95 --shifts 1.2 2.0 --reps 10
python dev/benchmarks/effect_size_benchmark.py --n-grid 5 6 10 12 --blocks 0 40 --rhos 0.95 --shifts 0.0 -1.2 --reps 10   # controls
```

Seed 20261022. The script always writes `effect_size_runs.csv` and `effect_size_summary.csv`; the committed tables from the three runs above were given distinct names by hand to keep them apart:

| File | Contents |
|---|---|
| `effect_size_summary_n5n6.csv`, `effect_size_runs_n5n6.csv` | 5–6 per state; blocks of 20 and 80 (10%, 40%); rho 0.95; shift 1.2 and 2.0; PhenoRewire, DiffCorr, DGCA |
| `effect_size_summary_n10n12.csv` | 10–12 per state, same effects, PhenoRewire only (summary only: that run's per-replicate file was overwritten by the next run) |
| `effect_size_summary.csv`, `effect_size_runs.csv` | controls (nothing differs; abundance change with the correlation kept) and pure rewiring, at 5, 6, 10 and 12 per state |

**Result**, fraction of replicates in which a difference is called:

| Per state | Block, shift | PhenoRewire | DiffCorr / DGCA |
|---|---|---|---|
| 5 | 10–40%, 1.2–2.0 | 0.0–0.5 | 1.0 |
| 6 | 10–40%, 1.2–2.0 | 0.2–0.9 | 1.0 |
| 10–12 | 10–40%, 1.2–2.0 | 0.5–1.0 | — |
| 5–12, controls | block 0; block 20%, shift −1.2 | 0.0–0.1 | — |
| 5–12, pure rewiring | 20%, shift 0 | 0.0 | — |

Below 14 samples per state a large reorganisation is detectable when the metabolites involved also change in abundance, because abundance is the only route by which they can be selected there. Pure rewiring with identical marginals is not detected at all below 14, as expected: those metabolites can only enter through connectivity-based selection, which does not run below 14 per state. The controls stay at or near zero throughout, so what is called below the operating range is not noise; what the sample size costs is sensitivity, not specificity.
